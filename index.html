Gatehouse

Every sign-in is checked, limited and logged.

  • Passwords are hashedStored only as salted digests, never as plain text.
  • Lockout after 3 failed attemptsMakes automated password guessing impractical.
  • One error message for every failureThe page never reveals whether the email or the password was wrong.
  • Idle sessions expireYou are signed out after 5 minutes without activity.
  • User text is never run as codeNames and emails are written to the page as plain text, which blocks script injection (XSS).
  • Roles limit who sees whatAdmin, Analyst and Viewer each get only the access they need (least privilege).
  • Two-step verificationA time-based code from an authenticator app is required after the password.

About this project

A front-end showcase of a secure sign-in flow. It includes:

  • Password hashing with a unique salt per user
  • Lockout after three failed attempts, for passwords and codes alike
  • Time-based two-step verification that works with Google Authenticator
  • Role-based access (Admin, Analyst, Viewer) with a 403 page
  • An audit log of sign-ins and blocked access
  • A security lab that simulates brute-force and SQL injection attacks

Built with plain HTML, CSS and JavaScript, no framework. The checks run in your browser, so this shows the design and the logic; a production system enforces every rule on a server.
